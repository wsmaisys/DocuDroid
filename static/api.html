🚀 Introduction

DocuDroid provides high-performance HTTP REST endpoints allowing you to initialize chat sessions, vectorize PDF documents in asynchronous workers, ingest web pages, and generate multimodal RAG responses using Mistral AI models.

Base URL: http://localhost:8080/
FastAPI OpenAPI 3.0

📋 Integration Lifecycle

  1. Step 1: Session Initiation — Call POST /session/init to obtain a unique session thread_id.
  2. Step 2: Document / Web Ingestion — Send files to POST /upload/pdf or URLs to POST /upload/web attached to your thread_id.
  3. Step 3: Background Worker Polling — Poll GET /status/{process_id} until indexing reaches completed.
  4. Step 4: Real-Time Reasoning — Submit queries to POST /chat with mode set to "general", "pdf", or "web".

⚡ Initialize Session

POST /session/init

Initializes an isolated RAG conversation session in memory and generates a UUID v4 thread_id.

cURL Example:

curl -X POST http://localhost:8080/session/init \
  -H "Content-Type: application/json"

200 OK Response:

{
  "thread_id": "84d720b5-6804-4c46-8807-6b4501a3b123",
  "message": "Welcome! You can:\n1. Chat generally\n2. Upload PDFs for analysis\n3. Share URLs for web content analysis"
}

💬 Send Chat Message

POST /chat

Dispatches a user query to the specified engine (General Mistral LLM, PDF RAG retriever, or Web RAG retriever).

Field Type Description
thread_idREQUIRED string UUID string received from /session/init
messageREQUIRED string The prompt text or question
modeOPTIONAL string "general" | "pdf" | "web" (Default: "general")

cURL Example:

curl -X POST http://localhost:8080/chat \
  -H "Content-Type: application/json" \
  -d '{
    "thread_id": "84d720b5-6804-4c46-8807-6b4501a3b123",
    "message": "Summarize the primary security concerns in the uploaded whitepaper.",
    "mode": "pdf"
  }'

200 OK Response:

{
  "response": "Based on the uploaded document, the primary security concerns include unauthenticated endpoints and insufficient input sanitization in legacy modules."
}

📄 Ingest PDF Document

POST /upload/pdf

Accepts a binary PDF file via multipart/form-data, initiates background chunking and embedding, and returns a process_id.

Form Key Type Description
thread_idREQUIRED string Session identifier
fileREQUIRED binary The PDF document to ingest (Max 50MB)

cURL Example:

curl -X POST http://localhost:8080/upload/pdf \
  -F "thread_id=84d720b5-6804-4c46-8807-6b4501a3b123" \
  -F "file=@/path/to/financial_report.pdf"

200 OK Response:

{
  "status": "processing",
  "message": "📄 Processing PDF: financial_report.pdf...",
  "filename": "financial_report.pdf",
  "process_id": "proc-84d720b5-6804-4c46-8807-6b4501a3b123"
}

⏳ Check Processing Status

GET /status/{process_id}

Polls status telemetry for background vectorization operations.

cURL Example:

curl -X GET http://localhost:8080/status/proc-84d720b5-6804-4c46-8807-6b4501a3b123

200 OK Response:

{
  "status": "completed",
  "message": "✅ Successfully processed financial_report.pdf. Vector embeddings loaded."
}

🌐 Ingest Web URL Content

POST /upload/web

Scrapes one or more web URLs, strips HTML boilerplate, and chunks text into vector embeddings.

Field Type Description
thread_idREQUIRED string Session identifier
urlsREQUIRED array[string] List of absolute HTTP/HTTPS URLs

cURL Example:

curl -X POST http://localhost:8080/upload/web \
  -H "Content-Type: application/json" \
  -d '{
    "thread_id": "84d720b5-6804-4c46-8807-6b4501a3b123",
    "urls": ["https://en.wikipedia.org/wiki/Retrieval-augmented_generation"]
  }'

200 OK Response:

{
  "status": "success",
  "message": "Successfully added web content from 1 URL(s)."
}

⚠️ HTTP Status Codes & Error Formats

Code Reason Scenario
200 OK Success Request executed and JSON returned
400 Bad Request Client Error Non-PDF file uploaded or missing arguments
404 Not Found Missing Process Invalid or expired process_id
500 Server Error Execution Failure Mistral API key missing or scraping timeout

⚡ Best Practices

  • Thread Isolation: Always instantiate a distinct thread_id per user session to avoid vector collision.
  • Status Polling: Use a progressive backoff (e.g. 1.0s, 1.5s, 2.0s) when polling /status/{process_id}.
  • Mode Alignment: Ensure PDF/Web modes are invoked only after successful vector ingestion.
